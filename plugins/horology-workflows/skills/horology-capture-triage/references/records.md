# Pipeline records

Read live Master headers and resolve fields by name; never assume column offsets. Use the Master table's filters to view one domain.

[Pipeline](https://docs.google.com/spreadsheets/d/1aL678ACs97YpLIGrGU5LbpXHc7jQBxl64ED-sLyehvI/edit) owns work selection, scope, stage and status. Its permanent numeric ID is independent of External ID, which can contain an optional historical ClickUp identifier. ClickUp Pipeline URL identifies the associated task. Document count is derived from Document Index, not a list of links. Current decision ID identifies the active Decision Register record.

Use Title, Domain, Entity, Type, Summary / Why, Next step / Research question, and Revisit trigger for capture. Domain and Entity must be values from the Domains tab; Entity is set only for a domain that lists entities ([domains, folders and templates](locations.md)). Preserve Created; update Updated for substantive edits with the actual date.

Write readable text in Summary / Why, Next step / Research question and Revisit trigger. Keep a single short thought on one line; put distinct points on separate lines, with a blank line between paragraphs when useful. Number ordered steps, one step per line. Save actual line breaks in the cell value, not the literal characters `\n`, and do not compress a list into one long sentence. Preserve the founder's line breaks when editing existing text. Read back multiline values to confirm the breaks survived.

Type is Idea, Research, Direction, Plan, Feature, Enhancement, Refactor or Fix, and chooses the route. Idea, Research, Direction and Plan take the investigation route; Feature, Enhancement, Refactor and Fix (a defect to correct) take the implementation route. Choose the Type that matches what the founder wants: a question to answer is Research or Idea even when it is about software; a change to make is Feature, Enhancement, Refactor or Fix.

Read the live status dropdown before writing. Inbox captures new work; Parked defers it; Researching indicates an authorised investigation; In progress indicates an implementation-route run planning or implementing; Awaiting decision requests founder review; Approved authorises the specified next-stage deliverable; Completed records saved Stage 4 work on either route (its proposed Specialist deliverable decision can still reopen it; implementations finished before 04/11/2026 ended at Stage 3); Rejected retains rejected work. Match the sheet's actual spelling. Stage identifies the current step; Review stage (Investigation proposal, Specialist deliverable or Implementation question) identifies what is under review. Every route starts with a Stage 1 specialist document in Drive (Research, Direction, Plan or Technical Assessment template) plus Steps rows. On the investigation route, Stage 1 work moves to Stage 2 for review, and after Stage 3 work is saved the supervisor makes the Stage 4 visual synthesis in the same run, proposes a Specialist deliverable decision and sets the item Completed at Stage 4; the founder accepts that decision or reopens the item with rework, park or reject. On the implementation route, the run writes its plan document and Steps rows at Stage 1, moves itself to Stage 3, implements, writes an Implementation report Google Doc from its template and finishes Completed at Stage 4 (a page is made from the report only on the founder's request) with a proposed Specialist deliverable decision, or stops at Stage 3 with an Implementation question that links the Stage 1 document; there is no Stage 2. Follow [workflow.yaml](workflow.yaml) and existing values.

Agent status is No action, Plan or Ready. Plan asks the planner to scope or split the item; the planner sets it back to No action when done. Ready selects the item for the platform named in Agent type; it does not launch a run, and it authorises implementation only for an implementation-route Type. Runs start when the founder asks a supervisor session to run Ready items.

Agent type is Claude Code, Codex, ChatGPT Work, Hermes, Manual or Unassigned; verify live selections. Each platform runs only its own rows. Manual is founder-led and never run by agents. Run location is Local or Cloud (blank means Local) and decides where the item's session runs. ChatGPT Work is Cloud only and is claimed by the Codex supervisor harness; Hermes is Local only, with Coordinator dispatching through Kanban and Operator claiming as Hermes. Planner output is Yes when the planner has written a sharper question or steps for the row; only the planner sets it. Default new captures to No action and Unassigned, with Run location blank, unless instructed otherwise.

Runs are recorded in the execution history through the document-graph connector (`claim_item`, `finish_run`), not in the workbook. The planner, or an implementation-route run at Stage 1, writes planned steps on the Pipeline's **Steps** tab (one row per step: Pipeline ID, Step, Task, Specialist, Status), and Next step stays a one-line question; capture never writes Steps. Proposed decisions keep a one-line Decision cell, with one row per option on the Decision Register's **Options** tab. The rules are in the supervisor skill's runs reference.

Link type, URL and GitHub branch identify the work target. Verify repo remote and branch before inspecting code. Supporting documents belong in Document Index. Graph Inclusion there is the founder's: agents add rows with it FALSE and never change it. A Decision Register row's Research Links holds Drive files only (Google Docs, Sheets, Slides or an HTML file in Drive), never a GitHub, Drive folder or web link; `check_register_write` refuses other links when they are passed as `research_links`. Repository files stay in the repository and are reached through the Drive document's Related Repo Document. Do not recreate removed Research / Plan links, Decision link or ClickUp execution link columns.

Permanent numeric IDs are never renumbered or reused. Pipeline IDs are allocated by the workspace's **Add Pipeline item** form under its script lock; when capturing directly in the sheet, use one capture writer at a time and re-read Master immediately before saving. Decision and Document IDs are never taken from the sheet: reserve each with the document-graph tool `reserve_id` (register `decision` or `document`, Pipeline ID, run ID) and call `check_register_write` before every register write; `ok: false` means the ID belongs to another item or Drive file, so stop and report instead of overwriting. Find every row by its ID immediately before writing it, never by row position or a row number read earlier. Use Pipeline ID in metadata because sheet row URLs move. Preserve unrelated cells and inspect ambiguous failures before retrying.

The allowed status and Agent status moves, and who may make each, are defined in [workflow.yaml](workflow.yaml). Follow it; a move not listed there is unexpected.
